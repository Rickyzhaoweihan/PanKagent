Donor-to-sample follow-ups:
Interpret 'these donors' using the prior verified backend donor population and unchanged cohort/source/stage/exclusion scope. Produce a standalone effective question retaining this scope. Formatter samples, displayed example IDs and aggregate counts are not complete backend identity sets. Never derive donor IDs from an aggregate count or make up IDs.
The graph direction is (d:donor)-[:HAS_SAMPLE]->(s:Sample_node). The assay filter belongs to s.data_modality, not a separate scRNA-seq sample node type. The same pattern applies to every recorded sample modality. Count DISTINCT s.id, not relationships or donors. Return matching sample identities and donor links for inspection when needed; an indexed sample does not prove downloadable files exist.
If complete verified donor IDs are supplied as backend scope, one HAS_SAMPLE query anchored to those donor IDs is sufficient. Do not repeat HAS_DONOR or require a disease/tissue witness merely to get samples. Never encode a previous run ID as a current-plan dependency. If verified IDs are unavailable to this plan, first retrieve the complete donor population using the preserved filters, then retrieve its samples. For this donor population step, retrieve donor identities rather than only a count.
For an ordinary donor-to-sample dependent step use relation_types=["HAS_SAMPLE"], depends_on=["donors"], input_bindings=[{"step_id":"donors","entity_type":"donor","source_role":"","target_role":"source"}]. The donor is the source endpoint; the sample is the target. target_role="donor" is invalid unless an explicit path_spec declares that role. No path_spec is needed for this single edge.
The sample constraint is {"entity_type":"Sample_node","property":"data_modality","operator":"=","value":<recorded modality label>}. Do not add HAS_DONOR to the sample step. Preserve HPAP/source, stage, polarity and independent clinical conditions in the donor retrieval; never guess the full stored clinical-stage sentence. Clinical metadata is resolved by the existing grounding pipeline.
Example: after 'How many T1D stage 2 donors are available in HPAP?', 'How many scRNAseq samples are available for these donors?' means count distinct Sample_node IDs connected to that exact verified donor cohort, with the recorded scRNA-seq assay scope. This is a normal donor-to-sample lookup, not a long connected-path request.
Modality entries below are terminology guidance, not authorization or inventory proof. Use runtime grounding to verify labels. Preserve negations, explicit exact-assay requests and the existing reviewed multiome capability policy.
